-- a building has multiple elevators and multiple floors
-- a user can req an elevator externally using up/down buttons at each floor
-- these up/down direction button is used to choose the best elevator to serve the req
-- one elevator is chosen , the floor is added in that particular elevator bucket list
-- a user inside a elevator can also press a button to destination floor
-- req selected inside the elevator should serve by the same elevator
-- idle when no req exists and awake when new arrives
-- up : visit floors in asc order
-- down : visit floors in desc order



objects -
Building
Floors
Buttons, internal/external
Elevator , elevatorManger ,
elevatorScheduler - maintains the elevatorcontrollers and has elevator selection strategy to choose the best elevator to serve
externalDispatcher - bridge between external buttons and elevatorManager(orchestrator)
internalDispatcher - pass request to each elevator manager



Elevation Selection Strategy
-- when the external button is pressed we have floor and the direction which user want to go to
-- when there are more than 1 elevator we need to select the strategy : nearest elevator (nearest to that particular floor should handle it )
                                                                         least busy elevator(the elevator having least requests should handle it )


------------

algos for optimal elevator solution


1. Scan algorithm
-- head moves in one direction first,servicing the requests along the way
-- once it reaches the end , it reverses the direction , so it moves end to end

2. Look algorithm
-- same as scan , don't go till the end , stop when there is no request (up -> stop at 12 if no req -> req from down -> go to 6 -> in between the req comes from 10 then fullfill it  )
-- can be impl by 2 pqs min and max (when going down use maxpq) if (up use minpq) we will go to a direction till the pq is not empty
